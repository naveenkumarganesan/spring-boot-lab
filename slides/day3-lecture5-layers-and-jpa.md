# Day 3 · Lecture 5
## Layered architecture and JPA

---

## Why layers?

```
[HTTP]    →   Controller    (parse request, return response)
              ↓
              Service       (business rules, transactions)
              ↓
              Repository    (database queries)
              ↓
[DB]          Database
```

Each layer has **one job**. You can replace any layer without affecting the others.

- Swap H2 for Postgres → only the repository / config layer changes.
- Add caching → goes in the service, not the controller.
- Add a new transport (gRPC, GraphQL) → new controller, same service.

---

## The vocabulary

| Term | What it is | Spring annotation |
|------|------------|-------------------|
| Entity | A Java class mapped to a DB table | `@Entity` |
| Repository | Database access (CRUD + queries) | `@Repository`, extends `JpaRepository<E, ID>` |
| Service | Business logic, transactional boundaries | `@Service` |
| Controller | HTTP entry point | `@RestController` |
| DTO | Data Transfer Object — API shape | (just a POJO) |

---

## JPA vs Hibernate vs Spring Data JPA

| Layer | What it is |
|-------|-----------|
| **JPA** | Specification — annotations, EntityManager, JPQL |
| **Hibernate** | Implementation of JPA (the actual ORM engine) |
| **Spring Data JPA** | Productivity layer on top — auto-generates repository implementations |

Spring Boot wires all three together via auto-configuration.

## Entity basics

```java
@Entity
@Table(name = "books")
public class Book {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private String title;

    @Column(unique = true)
    private String isbn;

    private int copies;

    public Book() { }   // JPA requires a no-arg constructor
    // ...
}
```

Annotations:
- `@Entity` — this class maps to a table.
- `@Table(name = "books")` — table name (defaults to class name).
- `@Id` + `@GeneratedValue` — primary key, autogenerated.
- `@Column` — constraints on the column.

## Spring Data JPA repository

```java
public interface BookRepository extends JpaRepository<Book, Long> {
}
```

That's it. You get:

| Method | What it does |
|--------|--------------|
| `findAll()` | All rows |
| `findById(Long id)` | `Optional<Book>` |
| `save(Book b)` | INSERT or UPDATE |
| `deleteById(Long id)` | DELETE |
| `existsById(Long id)` | boolean |
| `count()` | row count |

Spring generates the implementation at runtime. No code from you.

---

## Derived query methods

The method **name** is the query.

```java
public interface BookRepository extends JpaRepository<Book, Long> {
    List<Book> findByAuthor(String author);
    List<Book> findByTitleContaining(String fragment);
    List<Book> findByTitleContainingIgnoreCaseAndAuthorContainingIgnoreCase(
        String title, String author);
    long countByAuthor(String author);
    Optional<Book> findFirstByOrderByCopiesDesc();
}
```

Spring parses the name (`findBy<Field><Predicate>And<Field><Predicate>`) and generates SQL.

For anything more complex, use `@Query("SELECT b FROM Book b WHERE ...")` or a JPQL/native query.

## H2 — our learning database

- **In-memory** by default (lost on restart) or **file** (persisted).
- **Zero install.**
- **Web console** at `/h2-console` for interactive SQL.
- Same SQL dialect as most real DBs.

Config in `application.properties`:

```properties
spring.datasource.url=jdbc:h2:mem:librarydb
spring.jpa.hibernate.ddl-auto=update
spring.h2.console.enabled=true
```

`ddl-auto=update` tells Hibernate: "Create or update the schema based on `@Entity` classes."

---

## `data.sql` — seed data

`src/main/resources/data.sql`:

```sql
INSERT INTO books (title, author, isbn, copies) VALUES (...);
```

Spring Boot runs this at startup. Make sure to set:

```properties
spring.jpa.defer-datasource-initialization=true
```

so it runs **after** Hibernate creates the schema.

---

## The H2 console

Open `http://localhost:8080/h2-console`:

- JDBC URL: `jdbc:h2:mem:librarydb`
- User: `sa`
- Password: (empty)

You can run any SQL. Great for debugging — when your endpoint returns weird data, you can check what's actually in the DB.
